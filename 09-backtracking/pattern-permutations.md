# Pattern — Permutations, Grids & Constraint Search

The `used`-array family. **Order matters**, so every element stays available at every level.

---

## Permutations (LC 46)

```python
def permute(nums):
    res, path = [], []
    used = [False] * len(nums)

    def backtrack():
        if len(path) == len(nums):
            res.append(path[:])
            return

        for i in range(len(nums)):       # ⭐ starts at 0 every time — no `start` index
            if used[i]:
                continue
            used[i] = True
            path.append(nums[i])
            backtrack()
            path.pop()                   # undo
            used[i] = False              # undo

        # (nothing else to do)

    backtrack()
    return res
```
**O(n · n!)**

### The structural contrast with combinations

| | Combinations | Permutations |
|---|---|---|
| Loop starts at | `start` | **0** |
| Tracks | a start index | a `used` array |
| `[1,2]` vs `[2,1]` | same → one is generated | different → both generated |
| Count | C(n,k) | n! |

**One sentence:** *combinations move forward only; permutations may reach back, so they need a
`used` array to avoid reusing an element within the same path.*

### The swap variant (O(1) extra space)
```python
def permute(nums):
    res = []
    def backtrack(first):
        if first == len(nums):
            res.append(nums[:])
            return
        for i in range(first, len(nums)):
            nums[first], nums[i] = nums[i], nums[first]   # choose
            backtrack(first + 1)
            nums[first], nums[i] = nums[i], nums[first]   # un-choose
    backtrack(0)
    return res
```
Cleverer, but ⚠ **it does not extend cleanly to duplicate handling** — swapping destroys the sorted
order the duplicate rule relies on. Use the `used`-array version when duplicates are involved.

## Permutations II — with duplicates (LC 47)

```python
def permute_unique(nums):
    nums.sort()                          # ⭐ duplicates must be adjacent
    res, path = [], []
    used = [False] * len(nums)

    def backtrack():
        if len(path) == len(nums):
            res.append(path[:])
            return

        for i in range(len(nums)):
            if used[i]:
                continue
            if i > 0 and nums[i] == nums[i-1] and not used[i-1]:
                continue                 # ⭐ the rule
            used[i] = True; path.append(nums[i])
            backtrack()
            path.pop(); used[i] = False

    backtrack()
    return res
```

### Decoding `not used[i-1]`

Take `nums = [1a, 1b, 2]` (subscripts for identity only).

We want each distinct permutation once. So we impose a **canonical order**: among equal values,
always consume the earlier index first.

- `used[i-1] == True` → `1a` is already in the path → using `1b` now continues the canonical order ✅
- `used[i-1] == False` → `1a` is **not** in the path → starting with `1b` would produce a permutation
  identical to one generated by starting with `1a`. Skip. ❌

So the condition says: *"don't use a duplicate unless its identical predecessor is already used."*

> `used[i-1] == True` also works as a skip condition (some solutions use it) — it just enforces the
> reverse canonical order and prunes less efficiently. `not used[i-1]` prunes higher in the tree,
> so prefer it.

## Word Search (LC 79) — backtracking on a grid

> Does `word` exist as a path of adjacent cells? Each cell used at most once per path.

```python
def exist(board, word):
    R, C = len(board), len(board[0])

    def backtrack(r, c, i):
        if i == len(word):
            return True                          # matched everything
        if r < 0 or r >= R or c < 0 or c >= C:
            return False
        if board[r][c] != word[i]:
            return False

        tmp = board[r][c]
        board[r][c] = '#'                        # ⭐ mark visited (in place, no extra set)

        found = (backtrack(r+1, c, i+1) or
                 backtrack(r-1, c, i+1) or
                 backtrack(r, c+1, i+1) or
                 backtrack(r, c-1, i+1))

        board[r][c] = tmp                        # ⭐ UNDO — other paths may need this cell
        return found

    for r in range(R):
        for c in range(C):
            if backtrack(r, c, 0):
                return True
    return False
```
**O(R · C · 4^L)** where L = `len(word)`.

**The two things that make it backtracking rather than plain DFS:**
1. The cell is marked visited *temporarily* — only for the current path.
2. It's **unmarked on the way out**, because a different path may legitimately reuse it.

> **Contrast with Number of Islands**, where you mark cells visited *permanently* and never undo.
> That's flood fill — you want each cell counted once, globally. Here you want each cell used once
> **per path**. Understanding that difference is the point of this problem.

**Optimisation worth mentioning:** if `Counter(word)` has a character that appears more often than in
`Counter(board)`, return False immediately. Also, if the last letter is rarer than the first, search
the reversed word — it prunes far more.

## N-Queens (LC 51) — constraint propagation

> Place `n` queens on an `n×n` board with no two attacking each other.

**The idea that makes it fast:** place one queen per row (so rows are automatically safe), and track
attacked columns and diagonals in **sets**, giving O(1) safety checks.

```python
def solve_n_queens(n):
    res = []
    cols = set()
    diag = set()        # r - c  is constant along a ↘ diagonal
    anti = set()        # r + c  is constant along a ↙ diagonal
    board = [['.'] * n for _ in range(n)]

    def backtrack(r):
        if r == n:
            res.append(["".join(row) for row in board])
            return

        for c in range(n):
            if c in cols or (r - c) in diag or (r + c) in anti:
                continue                                   # attacked — prune

            cols.add(c); diag.add(r - c); anti.add(r + c)   # choose
            board[r][c] = 'Q'

            backtrack(r + 1)                               # explore

            board[r][c] = '.'                              # un-choose
            cols.remove(c); diag.remove(r - c); anti.remove(r + c)

    backtrack(0)
    return res
```

### The diagonal identities — worth memorising

```
r - c  is constant along  ↘  (top-left to bottom-right)
r + c  is constant along  ↙  (top-right to bottom-left)
```

```
r-c:              r+c:
 0  -1  -2         0   1   2
 1   0  -1         1   2   3
 2   1   0         2   3   4
```

These come up in matrix diagonal traversal, Sudoku-like problems, and bishop/queen movement anywhere.

**Why this pruning matters:** naive placement then validation is O(n^n). Checking constraints *before*
descending cuts the tree so aggressively that n=8 solves instantly.

## Letter Combinations of a Phone Number (LC 17)

The simplest multi-branch backtracking. Good for confirming the template is internalised.

```python
def letter_combinations(digits):
    if not digits: return []
    m = {'2':'abc','3':'def','4':'ghi','5':'jkl',
         '6':'mno','7':'pqrs','8':'tuv','9':'wxyz'}
    res, path = [], []

    def backtrack(i):
        if i == len(digits):
            res.append("".join(path))
            return
        for ch in m[digits[i]]:
            path.append(ch)
            backtrack(i + 1)
            path.pop()

    backtrack(0)
    return res
```

## Generate Parentheses (LC 22) — pruning by invariant

> All valid combinations of `n` pairs.

```python
def generate_parenthesis(n):
    res, path = [], []

    def backtrack(open_count, close_count):
        if len(path) == 2 * n:
            res.append("".join(path))
            return

        if open_count < n:                    # can always open, up to n
            path.append('('); backtrack(open_count + 1, close_count); path.pop()

        if close_count < open_count:          # can only close what's open
            path.append(')'); backtrack(open_count, close_count + 1); path.pop()

    backtrack(0, 0)
    return res
```

**The whole problem is those two conditions.** They guarantee validity *by construction* — no
generate-then-filter, no wasted branches. This is constraint pruning in its purest form: the invalid
subtree is never entered at all.

## Sudoku Solver (LC 37) — the pattern at full scale

Returns `bool` up the stack so the recursion can stop at the first solution.

```python
def solve_sudoku(board):
    rows = [set() for _ in range(9)]
    cols = [set() for _ in range(9)]
    boxes = [set() for _ in range(9)]
    empties = []

    for r in range(9):
        for c in range(9):
            v = board[r][c]
            if v == '.':
                empties.append((r, c))
            else:
                rows[r].add(v); cols[c].add(v); boxes[(r//3)*3 + c//3].add(v)

    def backtrack(k):
        if k == len(empties):
            return True                       # all filled → done
        r, c = empties[k]
        b = (r//3)*3 + c//3

        for v in "123456789":
            if v in rows[r] or v in cols[c] or v in boxes[b]:
                continue
            board[r][c] = v
            rows[r].add(v); cols[c].add(v); boxes[b].add(v)

            if backtrack(k + 1):
                return True                   # ⭐ propagate success — stop searching

            board[r][c] = '.'                 # undo
            rows[r].remove(v); cols[c].remove(v); boxes[b].remove(v)

        return False

    backtrack(0)
```

> **Return `bool` when you need *one* solution; append to a list when you need *all* of them.**
> That's the structural difference between "find a valid arrangement" and "enumerate all
> arrangements". Getting it wrong means either wasted work or a missing early exit.
>
> **Box index:** `(r // 3) * 3 + c // 3`. Worth memorising — it appears in every 9×9 grid problem.

## Debug checklist

- [ ] Every `append` has a matching `pop`; every `add` has a matching `remove`.
- [ ] Recording `path[:]`, not `path`.
- [ ] Permutations: loop from 0 with `used`. Combinations: loop from `start`.
- [ ] Grids: is the visited mark **undone** (backtracking) or **permanent** (flood fill)?
- [ ] Do I need **all** solutions (append to a list) or **one** (return `bool` and short-circuit)?
- [ ] Am I pruning before descending, rather than validating after?
